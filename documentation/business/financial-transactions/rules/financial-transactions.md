# Financial Transaction Rules

The rules below distinguish code-observed behavior from requirements explicitly confirmed by the business. Code-inferred rules remain subject to validation.

| ID        | Rule                                                                                                                                                                                                                                                                                                                                                                                                  | Status                    |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| BR-TX-001 | A transaction has direction `INCOME` or `EXPENSE` and a strictly positive amount. Direction, not the sign of the amount, indicates whether it is an inflow or outflow.                                                                                                                                                                     | Needs business validation |
| BR-TX-002 | A transaction may be assigned to an accounting month different from its transaction date. When saved, the day is normalized to the first day of that month.                                                                                                                                                                                | Needs business validation |
| BR-TX-003 | A lease may only be linked to an income transaction.                                                                                                                                                                                                                                                                                                                                                 | Needs business validation |
| BR-TX-004 | A subcategory's direction must be compatible with the transaction direction; a subcategory defined for both directions is compatible with either.                                                                                                                                                                                         | Needs business validation |
| BR-TX-005 | A `RECONCILED` transaction cannot be modified or deleted through the observed operations.                                                                                                                                                                                                                                                 | Needs clarification       |
| BR-TX-006 | Partial amounts assigned to equipment links must not total more than the transaction amount.                                                                                                                                                                                                                                               | Needs business validation |
| BR-TX-007 | A manually entered transaction is created as `CONFIRMED`; an imported row with per-row review data (optional overrides for direction, classification, lease, housing unit, building, or equipment links) is created as `CONFIRMED`, even when all those values are unset, while a row without this review data is created as `DRAFT`. | Needs clarification       |
| BR-TX-008 | A transaction can only be accessed or processed within the estate to which it belongs.                                                                                                                                                                                                                                                      | Needs business validation |
| BR-TX-009 | During import, duplicate detection uses a 64-character lowercase hexadecimal SHA-256 digest of UTF-8 text formed by joining the ISO transaction date, amount rendered without trailing zeroes, counterparty account trimmed and uppercased (or blank when absent or `-`), and the first 60 characters of the trimmed, uppercased description with whitespace collapsed, using `|`; a matching digest in the same estate causes the row to be skipped. | Needs business validation |
| BR-TX-010 | The transaction list must not calculate or return aggregate financial totals; aggregate totals belong in a separate dashboard.                                                                                                                                                                                                             | Confirmed                 |
| BR-TX-011 | A single expense transaction may cover multiple costs, and its amount may be allocated across those costs whether or not they are linked to equipment.                                                                                                                                                                                     | Confirmed                 |
| BR-TX-012 | A manually entered transaction may be created with status `DRAFT` or `CONFIRMED`, with `CONFIRMED` as the default; later status changes must be made through a dedicated action, not the transaction edit operation.                                                                                                                           | Confirmed                 |
